# AGENTS.md

MyTetra — кроссплатформенное Qt-only приложение, сборка через qmake (CMake в
проекте нет). Перед правкой кода прочитай раздел «Соглашение о кодировании» в
`README.md` (строки 32–60): он обязателен и местами противоречит тому, как уже
написан соседний код.

## Сборка

`qmake` не в PATH. Единственный доступный Qt 5.15.2 (путь зависит от машины):

    Q=/media/user/m2data/Qt_deb11/5.15.2/gcc_64
    # или
    Q=/media/user/data/Qt_installed/5.15.2/gcc_64

Сборка вне исходников — предпочтительный вариант, не засоряет репозиторий:

    # Тот же Q что выше, под свою машину
    mkdir -p /tmp/mt-build && cd /tmp/mt-build
    $Q/bin/qmake /путь/к/mytetra-dev/mytetra.pro
    make -j$(nproc)

Результат — `app/bin/mytetra` и `app/bin/mimetex` относительно каталога сборки.
`README.md` предлагает `qmake . && make` внутри репозитория; это работает, но
создаёт артефакты в дереве исходников.

Сборка НЕ чистая по предупреждениям: около 300 warning при 0 ошибок, `-Wall
-Wextra` включены в `app/app.pro`. Почти все (около 290) — из legacy C-файла
`thirdParty/mimetex/mimetex.c`, в коде приложения их около десятка
(deprecations Qt). Не считай warnings регрессией и не пытайся исправить
их разом — получится огромный посторонний diff. Но новый код не должен
добавлять предупреждений в `app/src/`.

Особенности сборки:

- `mimetex` собирается как отдельный бинарь (`TEMPLATE=app`), и `QMAKE_POST_LINK`
  копирует его рядом с `mytetra`. Формулы рендерятся запуском этого бинаря из
  `applicationDirPath()` (`app/src/libraries/wyedit/formatters/MathExpressionFormatter.cpp`),
  поэтому `mimetex` обязан лежать рядом с `mytetra` — иначе формулы молча не
  рисуются.
- `mytetra.pro` — `TEMPLATE=subdirs`, и `app` зависит от `mimetex`. Сборка
  только `app` неполна.
- Бинарь `mimetex` собирается в дерево исходников
  (`thirdParty/mimetex/build/bin/mimetex`) даже при сборке вне исходников.
  Каталог занесён в `.gitignore`, так чтоstatus не засоряется.

## Тесты

Автотестов, тест-фреймворков, CI, pre-commit хуков и конфигурации линтера в
репозитории нет вообще. Проверка = сборка + ручной или e2e-прогон.

Headless-прогоны виджетов работают через линковку тестового `.cpp`
со всеми `.o` приложения (кроме `main.o`) и запуск с
`QT_QPA_PLATFORM=offscreen`. Рабочий каталог-тест: бинарь рядом с
`conf.ini`, в `main()` повторить `setMainProgramFile(argv[0])`,
`globalParameters.init()`, `mytetraConfig.init()`. Выход через `_exit()`,
а не `return`: деструктор глобального `AppConfig` делает `sync()` уже
после смерти `QApplication` и падает в Qt-кодеках. Модалки в тестах
закрывать через `QTimer::singleShot`, иначе виснет навсегда. Прогоны
строго в `offscreen`: обычный запуск открывает настоящее окно и трогает
данные пользователя.

Грабля тестов: виджеты пишут в `editorconf.ini` из
`app/bin/resource/standartconfig/any/`. Перед коммитом проверять
`git status` и откатывать файл, он должен оставаться нетронутым.

Приложение однопроцессное: `QtSingleApplication` лежит в исходниках
(`app/src/libraries/qtSingleApplication5/`), поэтому опции `--control` работают
только при уже запущенном экземпляре.

Коды возврата `mytetra` (`app/src/main.cpp`, `parseConsoleOption`):
`0` успех или `--help`; `1` переданы опции без `--control`; `2` `--control` без
запущенного экземпляра; `3` обычный запуск при уже запущенном экземпляре;
`4` отсутствует обязательный параметр опции или опция управления неизвестна.

Данные ищутся в таком порядке (`GlobalParameters::setWorkDirectory`):
`./conf.ini` (портативный режим) → `~/.mytetra/` → `~/.config/mytetra/`.
Чтобы изолировать прогон, скопируй дерево `app/bin` в отдельный каталог,
положи туда `conf.ini` и запускай оттуда — тогда тест не трогает данные
пользователя.

## Добавление файлов

`app/app.pro` перечисляет `SOURCES` и `HEADERS` явно, без wildcard-ов: новый
`.cpp`/`.h` не попадёт в сборку, пока не внесён в `.pro`.

В `.pro` присутствуют обе версии `qtSingleApplication` — для Qt4
(`src/libraries/qtSingleApplication/`) и для Qt5 (`.../qtSingleApplication5/`),
qmake выбирает по `QT_MAJOR_VERSION`. Правь Qt5-вариант.

## Стиль

Требования `README.md` обязательны: UTF-8, табы запрещены, отступ 4 пробела,
`{` и `}` на отдельных строках, комментарии на русском или английском,
Qt-контейнеры вместо STL, include guards вида `_ИМЯ_КЛАССА_H_`, комментарий о
назначении каждого нового метода и о назначении класса в заголовке.

Сверх README стоит знать:

- В существующем коде правило скобок нарушено местами (`if(условие) {`).
  Не переформатируй чужой код, держи diff минимальным.
- Файлы в UTF-8 с LF. Не переводи их в CRLF.
- `*.sh` занесён в `.gitignore` — скрипты проверки нельзя закоммитить,
  держи их вне репозитория, например в `/tmp`.
- `history.txt` устарел и заканчивается словами «Далее история хранится в
  Git». Не дописывай в него.

## Git

Ветки: `master` — стабильный релиз, `experimental` — разработка; изменения из
feature-веток вливаются в `experimental`. Upstream — `xintrea/mytetra_dev`,
история принадлежит `xintrea <xintrea@gmail.com>`.

Каталог `build/` (shadow-сборка QtCreator) не отслеживается и НЕ занесён в
`.gitignore`, поэтому `git status` постоянно показывает `?? build/`. Он
содержит не только объектные файлы, но и данные приложения (`conf.ini`,
`data/base/…`, `actionLog.txt`), если программа запускалась из него. Никогда не
делай `git add -A` — заберёшь около 2000 файлов. Индексируй файлы явно.

## Известные грабли

- **Qt 5.15.2 + OpenSSL 3 в рантайме = проверка сертов мертва.** Qt собран под
  OpenSSL 1.1.1, символы вроде `SSL_get_peer_certificate` не резолвятся, и
  КАЖДОЕ https-соединение дает `QSslError::NoPeerCertificate` ("The peer did
  not present any certificate"), даже с валидным сертом. Валидный,
  самоподписанный и подмененный серты неразличимы, поэтому блокировать
  здесь бессмысленно - это ломает скачивание, не останавливая атак.
  `Downloader::onSslErrors` в такой среде качает с предупреждением в лог
  (см. `isTlsVerificationBroken`). На здоровом бэкенде действует строгая
  политика с точечным игнором только самоподписанности по галочке
  `ignoreSelfSignedSslErrors`.
- **Границы в `QList`/`QVector`**: `at()` не бросает исключение, а срабатывает
  assert и завершает процесс с кодом 134. Индекс нужно проверять до обращения.
  На этом уже падали `RecordTableData` и `MainWindow::messageHandler`.
- **`thirdParty/mimetex` — legacy C, конфликтует с современной glibc.** Файл
  определял `strcasestr()`, который glibc уже объявляет в `string.h` с другим
  прототипом, из-за чего возникала ошибка линковки. Символ переименован в
  `mimetex_strcasestr`; не возвращай POSIX-имена функций в этот файл.
- **Код возврата 0 не доказывает, что команда выполнена.** `sendMessage()`
  возвращает `bool`, но в `parseConsoleOption` результат игнорируется, и клиент
  завершается с кодом 0 даже при неудачной доставке команды.
- **`QLineEdit` сам управляет комплитером, заданным через `setCompleter()`:**
  префикс ставится на всю строку. Для многотокенного дополнения
  (теги через запятую, запрос из слов) привязывать через `setWidget()`
  и вести привод вручную из `textEdited`, иначе подсказка после
  разделителя не появляется.
- **`QTextCursor::insertBlock()` в начале абзаца оставляет курсор в остатке,**
  а не в новом пустом абзаце. Пустой абзац в произвольной позиции
  детерминированно дает связка «разрыв, разрыв, шаг назад» с пробами
  `StartOfBlock`/`EndOfBlock` (см. историю спойлеров).
- **`QTextDocument::toHtml()` сохраняет якоря, включая fragment-href, но
  молча роняет ПУСТЫЕ якоря.** Невидимому маркеру нужен невидимый символ
  (например `\u200B`), иначе маркер исчезнет при сохранении.
- **`lupdate` идет 5+ минут и мусорит.** Холодный парсинг 330 файлов
  занимает минуты (в основном ожидание), в конце в cwd остается
  временный `ekuTrR.json` (при обрыве не удаляется), а при запуске
  из корня репозитория — еще и `.qmake.stash`. Оба файла удалять
  руками, в коммит не тащить. Переводы править только в `.ts`,
  `.qm` пересобирать `lrelease` в том же коммите.
- **Тесты живут в `tests/` (ветки `feature/qttest-harness`,
  `experimental-sco-fix-and-features`), в `experimental` их нет.**
  Первая очередь без GUI (`QTEST_APPLESS_MAIN`), вторая и третья
  через harness: линковка всех `.o` приложения кроме `main.o`,
  `conf.ini` и фикстура копируются в каталог сборки сами,
  выход только через `_exit()`. Подробности в `tests/README.md`.
  `_exit()` глушит сброс покрытия gcov: harness зовет `__gcov_dump()`
  вручную (`-lgcov` уже в `mytetra_harness.pri`).
