# MyTetra — настройка обмена через Syncthing

> Руководство пользователя. Технический дизайн — в `06_shared_branch_exchange.md`.
> Статус: актуально (макет `local/` + `sync/` + единый `.git`, ADR-016).

## 1. Что синхронизируется, а что — никогда

Единственная общая папка Syncthing — **`shared/sync/`** внутри каталога обмена.
Всё остальное в синхронизацию **не входит и входить не должно**:

| Путь | Синхронизируется? | Почему |
|---|---|---|
| `shared/sync/` | **Да, только он** | Зеркало публикаций: `branch.xml`, `records/`, `meta.json`, `changelog.json`, `manifest.json` |
| `shared/local/` | Нет | Авторитет владельца (исходники публикаций до выкладки) |
| `shared/.tmp/` | Нет | Сборка версий |
| `shared/.git/` | Нет | Локальный журнал истории (у каждого свой) |
| `data/` (личная БД) | **Нет, никогда** | Local-first: чужие правки не должны попадать в вашу базу сами |
| `trash/`, `*.ini` | Нет | Корзина и настройки локальны |

Каталог обмена по умолчанию — `shared/` рядом с бинарником, меняется
в настройках на странице «Команда». Общая папка Syncthing должна указывать
**ровно на `shared/sync/`**, а не на `shared/` и тем более не на каталог
с базой. Ошибка здесь — самый опасный момент всей настройки.

Файл `shared/sync/.stignore` MyTetra создаёт сама (временные файлы сборки
и promotion). Свои исключения, которые трогают `branch.xml`, `records/`,
`meta.json`, `changelog.json` или `manifest.json, добавлять нельзя —
подписчики перестанут видеть целостные версии.

Версионирование файлов самого Syncthing для этой папки — **выкл**:
история версий уже есть (локальный git-журнал + корзина), а копии
версий Syncthing только раздувают трафик и смущают проверку целостности.

## 2. Быстрый старт

### 2.1. Владелец (первое устройство)

1. В MyTetra откройте настройки, страницу «Команда»: введите имя и email —
   коллеги будут видеть их как владельца ваших веток. Путь обмена по умолчанию
   подходит в большинстве случаев.
2. В дереве правый клик по ветке → «Опубликовать в общую папку…».
   Зашифрованная ветка публикуется расшифрованной и только с вашего согласия.
3. Дальше ветка обновляется **автоматически** при каждой правке
   (тексты — с задержкой в несколько секунд). Вручную дожать можно пунктом
   «Force branch update / recovery...» — он же чинит зеркало, если что-то побилось.

### 2.2. Подписчик (второе устройство)

1. В Syncthing добавьте общую папку с путём `<каталог обмена>/shared/sync`
   и примите её на первом устройстве (Folder ID должен совпасть —
   проще принять входящий запрос, чем вбивать ID вручную).
2. Дождитесь окончания синхронизации на обоих концах.
3. В MyTetra, панель «Подписки»: новая ветка появится в группе «Доступно»
   с именем владельца → «Подписаться». Первый импорт создаст полную копию
   в `imported/<владелец>/<ветка>` вашей личной базы.
4. Обновления владельца приходят как список «Что изменилось» —
   забираете вручную и выборочно («Show changes / Import...»).
   Автоимпорта нет и не будет: чужие правки не попадают в базу сами.

## 3. Рекомендуемые настройки папки Syncthing

- **Folder Path**: `.../shared/sync` (ещё раз: именно `sync/`, не `shared/`).
- **Folder Type**: Send & Receive на всех устройствах. Порядок «один писатель»
  обеспечивает сама MyTetra (каталог `sync/<владелец>/` пишет только владелец),
  на уровне Syncthing ничего ограничивать не нужно.
- **File Versioning**: Off.
- **Rescan Interval**: watcher Syncthing включён по умолчанию и ловит изменения
  сразу; интервал рескана 300–3600 секунд — страховка. Меньше 60 ставить
  не стоит (лишняя нагрузка на ноутбуках).
- **Ignore Patterns**: управляются MyTetra (`sync/.stignore`), руками не править.

## 4. Как проверить, что всё доехало

Зелёные флаги (всё хорошо):

- публикация видна в «Доступно» / подписка без пометок;
- срез («Open slice...») открывается, тексты читаются;
- номер версии в свойствах совпадает с номером у владельца.

Красные флаги:

- пометка «…» / «обновление в пути» — версия доехала частично: ждать
  и нажать «Проверить статус», не импортировать;
- предложение «Восстановить sync/ из журнала/local» при старте — область
  данных побита: соглашайтесь (сначала из `local/`, это без git);
- файлы `*.sync-conflict-*` внутри `sync/` — Syncthing зафиксировал
  параллельную запись. MyTetra их игнорирует (не импортирует, не удаляет).
  Разберите конфликт в файловом менеджере: оставьте правильный вариант,
  чужой удалите, затем на стороне владельца — «Force branch update».

## 5. Troubleshooting

| Симптом | Причина | Что делать |
|---|---|---|
| Публикации не появляются вообще | Общая папка указана на `shared/` вместо `sync/`; папка не расшарена/не принята; Syncthing на паузе | Проверить путь, расшаривание, статус соединения; подсказка есть и в пустой панели «Подписки» |
| Вечное «…» / «в пути» | Недоставка (сеть, место на диске), либо владелец не дожал публикацию | Подождать схождения Syncthing; проверить место; владелец жмёт Force update |
| Предложение восстановления при каждом старте | `sync/` пуста или побита | Восстановить (сначала из `local/`); если повторяется — смотреть диск/права |
| В журнале сотни снимков, предупреждение о размере | Нормальный рост (десятки МБ на тысячу) | «Архивировать историю» из меню (необратимо, останется текущее состояние) |
| Владелец переименовал ветку/профиль — каталоги не поменялись | Так задумано: имена каталогов фиксируются при первой публикации, актуальные названия — в `meta.json` | Ничего не делать |
| Подписчик удалил у себя импортированную копию, владелец обновил ветку | Придёт как новая запись (связь потеряна) | Импортировать заново или игнорировать |

## 6. FAQ

**Работает ли офлайн?** Да. Владелец публикует и правит без сети —
коммиты локальные; Syncthing разнесёт при появлении связи. Подписчик смотрит
последний доехавший срез; импорт ждёт целостной версии.

**Android?** Syncthing ставится из F-Droid/Play, MyTetra собирается под
Android. Нюанс: внешнего `git` на телефоне обычно нет — дифф, импорт,
детект и восстановление из `local/` работают, журнал/восстановление
из `.git` показывают подсказку. Пути `shared/` на Android — через
настраиваемый каталог обмена.

**Права доступа?** Пользователь Syncthing должен читать и писать `sync/`
на всех устройствах (владелец пишет, подписчику достаточно чтения,
но Send & Receive проще и безопасен благодаря правилу одного писателя).

**Несколько владельцев одной ветки?** Запрещено архитектурно: пишет только
владелец публикации. Коллеги забирают через импорт и публикуют своё.

**Шифрованные ветки?** Публикуются только расшифрованными и только
с явного согласия владельца. «Как есть» шифрованное не публикуется —
подписчики не смогли бы это прочитать и сравнить.

**Потерян весь `shared/` (включая `.git`)?** Локальный журнал тоже потерян —
восстановление только из внешнего бэкапа. Держите бэкап каталога обмена
(подойдёт и версионирование Syncthing на *соседней*, не общей папке).
