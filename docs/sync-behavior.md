# Wi-Fi sync: поведение клиента и гарантии безопасности

Дата: 2026-11-16. Плоскость: Android (MyTetroid `feat/sync-wifi`) и
десктоп-хаб (mytetra-dev `develop-v1-sync`). Протокол — `docs/sync-proto-1.md`,
планы — `docs/sync-plans.md`.

Десктоп: галки ✓/✕ чуть скруглены (6px, светлая тема), кнопка перехода
«↓N» красная (#EF5350, радиус 10px), между «Действия» и переходом —
«Развернуть всё»/«Свернуть всё», по умолчанию всё развёрнуто.

Галка «Sync server» (меню Sync десктопа) запоминается между запусками:
была включена — слушатель поднимается при старте молча; порт занят —
флаг сбрасывается без модалок.

Документ фиксирует КАК ведёт себя синк для пользователя (и почему это
безопасно), чтобы новые правки не разрушали накопленные гарантии.

## Главный принцип

Ничего не терять молча. Создание/переименование — могут применяться
автоматически; удаления и правки существующего — только явным выбором
пользователя. Любая потеря журнала/сайдкара деградирует в безопасную
сторону («пропало ≠ удалено», воскрешение вместо тихой потери).

## Окно «Дерево изменений»

- Полноэкранное: 60% дерево / 30% панель записей / 10% кнопки.
- Три вкладки с git-статистикой в заголовках:
  - **↑ Я → сервер** — моё новое (создано) и мои правки;
  - **↓ Сервер → я** — чужое новое и чужие правки;
  - **⇅ Обоюдные правки** — все расхождения текста; поединок версий
    (эвристика «новее побеждает» предлагает победителя, подтверждение
    тапом «↑ Наша» / «↓ Ихняя»).
- Значки: `+` создано, `≡` имя, `~` текст, `−` удалено.
- По умолчанию каждая вкладка показывает своё дерево; галочка «Всё
  дерево» — единое дерево с приглушением контекстных узлов
  (максимально бледные/прозрачные).
- Справка/легенда — иконка ⓘ на строке инструментов
  (Действия ▾ / Всё дерево / ⓘ).

## Окно выбора в десктопном синке (Devices → Sync)

- Кнопка Sync в диалоге устройств (`SyncDevicesDialog::onSyncNow`)
  показывает то же окно предпросмотра с выбором действий, что и
  `runSyncToHeadless`: встречные правки больше не решаются тихо
  по mtime без ведома пользователя (баг «окна выбора не было»,
  2026-11-16).
- Диалог переработан по концепции мобильного «Дерева изменений»
  (`SyncPreviewDialog`, 2026-11-16): заголовок со счётчиком
  «✓ Всё разобрано (d/m)» + галочка «Запомнить»; три вкладки
  «↑ Я → сервер» / «↓ Сервер → я» / «⇅ Обоюдные правки» с
  git-статистикой (цветные цифры `+2 ≡1 ~3 −1` иконками вкладок);
  строка инструментов «Действия ▾» (умолчания категорий), кнопка
  «ⓘ» (справка); одно окно: карта убрана,
  кружок-прогресс в шапке (зелёная дуга — разобрано, красная — остаток,
  в центре «d/m», тап — прыжок к первому неразобранному);
  одно дерево целиком с разделами-линейками «── ↑ Я → сервер · k ──» /
  «── ↓ Сервер → я · k ──» / «── ⇅ Обоюдные правки · k ──» (обоюдные —
  все Edit, остальное — по направлению); вкладки — якоря-ссылки
  (тап скроллит к разделу, фильтра нет); у строк иконки вместо комбо:
  единое правило без инверсий: ✓ = «делай как написано в строке»
  (применить направление: своё уедет, ихнее приедет, своё удаление
  выполнится), ✕ = «наоборот» (своё — взять с сервера, ихнее —
  настоять на моём) / diff, у обоюдных — дуэль «↑ Наша» /
  «↓ Ихняя» + diff; Skip умер (нерешенное = Confirm блокирует
  «Применить»); маркеры `+`/`≡`/`~`/`−` в цветах категорий, имена — в
  пилюлях цвета категории, стрелки `↑`/`↓`, красная `⚠` опасности;
  нерешенное подсвечено (жирный + тёплая подложка / пульс на мобиле),
  подсветка целиком разобранных веток; панель diff с поединком
  «↑ Наша»/«↓ Ихняя» и diff видимого текста (без HTML-мусора
  редакторов; картинки — строками «[картинка: имя]»; git-раскраска
  +/−; вкладки «Наша»/«Ихняя»/«Diff» с полными текстами сторон;
  у веток — те же три вкладки (имена: «Наша»/«Ихняя»/«Diff»,
  ownName/otherName из обоих манифестов);
  у иконок тултипы с исходом (дуэль показывает исход, а не generic;
  переименование ветки — чьи имена, правка — чья версия полная),
  повторный тап снимает решение;
  предзаполнен только Create (безопасное добавление), всё остальное —
  пустой Confirm: оба удаления требуют явного решения и до него
  красные; «Применить» активно при хоть одном решённом: всё разобрано —
  синкает и закрывает окно, разобрано частично — спрашивает
  «Синхронизировать только N из M?» («Оставшиеся элементы можно
  синхронизировать позже в этом же окне») и при «Да» выполняет решённое
  тем же мини-планом, а дерево локально сужается до остатка (без запросов
  к серверу; десктоп — зеркально, через тот же раннер); свайп строки
  вправо —
  «синхронизировать только это» (ветка — целиком с поддеревом,
  заметка тянет и недостающих предков из того же превью — иначе ей
  некуда вставать, no-branch; диалог с новой строки пишет «Дополнительно
  будет синхронизирована структура веток:» + дерево предков с отступом
  1 пробел на уровень):
  выполняется мини-планом сразу, строка исчезает из дерева
  (перестройка локальная, сервер дёргается один раз — на выполнение;
  остаток поддерева встаёт под серый пунктирный stub предка),
  альбомная: шапка — один ряд (заголовок диалога и первая строка скрыты,
  кольцо 32 без пояснений левее «Я → сервер», вкладки в одну строку,
  «Действия/Состав/ⓘ/Запомнить» влиты в тот же ряд; поворот перестраивает
  шапку на месте, решения/скролл/справка сохраняются),
  остаток добивает «Применить»; свайп по нерешённому просит сначала
  выбрать действие; полное «Применить» — когда всё разобрано
  (неактивна сереет, клик невозможен, раннер перепроверяет гейт);
  гонка данных — окно прогресса (незакрываемое): две полосы «↑ Туда» /
  «↓ Оттуда» (done/total по штукам, байтовые итоги заранее неизвестны),
  счётчики «Ветки: ↑a/b ↓c/d · Заметки: ↑e/f ↓g/h», скорость «↑/↓ N МБ/с»
  (замер тел запросов/ответов в клиенте, окно ~3с), таймер фазы, текущая
  запись мелким; апдейты троттлятся (~150мс);
  манифест строится одним обходом дерева (было O(n^2) — минуты и 100% CPU
  на 100k, клиент рвал по таймауту, сервер молотил мёртвому сокету);
  выборка манифеста — таймаут 120с (15с для остального);
  справа над деревом плавающий красный кружок
  «↓N» — прыжок по местам вмешательства (тап циклично ведёт
  к следующему нерешенному, цифра — остаток; свёрнутое пропускается;
  кружок прижат вправо сразу под вкладками); пустые разделы пишут
  «Ничего нет»; линейки разделов — на всю ширину (разрыв страницы);
  порядок — DFS-дерево (дети строго под своей веткой);
  тип сущности — рисованные иконки (жёлтая папка-классика, белый
  лист портретом с серым контуром); агрегат действий
  поддерева («+2−1») скрыт по умолчанию, показ — галочка «Состав»
  между «Действия» и «ⓘ»; решение живёт только на иконках;
  у веток с видимыми детьми тоггл «[+]»/«[−]»
  сворачивания поддерева; дуэль предлагает более новую по mtime
  (размер при равных байтах молчит), решения — «оставляем наш вариант» /
  «перетираем с сервера»; переименование ветки выбирается дуэлью
  «Наша»/«Ихняя», как у правок текста; предки вне синка — серые пилюли той же
  линии дерева (меньше, без иконок, пунктирная рамка, общие по id —
  без дублей),
  [+] в фиксированном гуттере слева от пилюль (отступы дерева
  не нарушаются); [+] слева у корня цепочки раскрывает вложения (серые общие по id,
  дубли исключены; цепочка — та же линия дерева); прыжок подсвечивает
  цель двойным плавным миганием 2×300 мс (альфа+подложка);
  неактивные иконки серые, активные — сплошная заливка + белый глиф;
  компактно: пилюли 13sp/серые 11sp, строки 1dp, индент 12dp, поля 12dp;
  неактивная «Применить» серая; защита от бития (почти-пустое не
  затирает содержательное: баннер, авто-дефолт «полная версия»,
  пометка `⚠`); кнопки «Отмена»/«Применить».
  Умолчания категорий общие для обоих путей синка
  (`SyncPreview::serializeDefaults/defaultsFromString`, конфиг
  `syncPreviewActions`).

## Галочка «Синхронизировать шифрованные ветки»

Настройка: Настройки → Синхронизация. **По умолчанию включена**
(прежнее поведение — слепая синхронизация шифртекста).

Выключена → зашифрованные ветки вместе с поддеревьями и их записи
**невидимы для синка** (не скачиваются, не загружаются). Три защиты
от тихих сюрпризов:

1. **Симметричный фильтр** (`SyncCryptFilter`): скрываются элементы
   ОБОИХ манифестов (своего и серверного) до планировщика. Если бы
   скрывался только свой манифест, исчезнувшее локально выглядело бы
   как «новое на сервере» и молча скачалось бы (та же ловушка, что
   была с надгробиями).
2. **Надгробия не фильтруются**: удаление зашифрованной ветки всё
   равно доедет до пира — иначе ветка воскресла бы.
3. **Честность**: в отчёте синка строка
   «🔒 Скрыто зашифрованных: N (галочка синка выключена)» —
   данные не «исчезают» без объяснений.

Протокол при этом не меняется: шифртекст ездит как есть, пароль не
ходит никогда (см. §13 протокола). Галочка — чисто клиентский фильтр
планирования.

## Маскировка имён шифрованного

Имена шифрованных элементов — base64-шифртекст (нечитаем), когда
хранилище открыто без пароля («кривые имена» в UI). Вместо мусора в
дереве и на панели показывается честный маскер
**«🔒 Зашифрованная ветка / запись»** — независимо от состояния
галочки (лечит UX независимо от настройки).

## Пара и кольцо устройств

- Спаривание — по общему PIN с двух сторон (диалог Sync devices:
  Pair/Accept со сверкой фингерпринта, headless — `--sync-pair`).
- У человека 4–5 устройств (ПК, ноут, телефоны, планшет): у каждого
  пира свой попарный секрет (кольцо `syncDevices/<id>/secret` +
  легаси-первая пара). Второй/пятый device добавляется той же
  процедурой Pair/Accept и НЕ разрывает остальных; удаление —
  точечное (Unpair/Remove), сброс всего — Reset all / `--sync-forget`.
- Сервер видит стучащихся даже при отказе hello (строка в списке
  без доверия): «клиент пишет secrets differ, а сервер его даже
  не видит» — закрыто.
- Первая пара в кольце — эпоха (спрос стратегии + чистка tombstone'ов);
  присоединение следующих устройств стратегию спрашивает, а журнал
  не трогает (чужие отложенные удаления не страдают).

## Надгробия (журнал удалений)

- Локальные удаления пишут надгробия (MyTetroid:
  `SyncLocalDeleteRecorder` + `SyncSidecarFactory`; хаб: `mytetra.sync`).
- Вырезание (cut) — без надгробий: элемент переезжает, а не исчезает.
- Удаления применяются только после явного выбора пользователя.
  Дефолт для категории «Мои удаления» в превью — «Взять с сервера»
  (воскрешение), оставлен как страховка.
- Потеря журнала = потеря надгробий и риск воскрешения удалённого —
  это осознанная деградация в «безопасную» сторону (данные не теряются).

## Превью-гейт

Скачивание новой ветки никогда не применяется молча
(`needsAttention`); merge-by-name проходит через единый preview-гейт
(`applyPreview`). Созданное/переименованное — молча, как договорились.

## Диагностика в отчёте синка

- «Журнал синка: надгробий N» — сколько надгробий видел журнал на
  момент синка (проверка результата `save()` у рекордера).
- «🔒 Скрыто зашифрованных: N» — только если галочка выключена.

## Известные проблемы

- **SIGSEGV при открытии заметки после синка в GUI** (баг от
  2026-11-16, корень найден 2026-11-16 по присланному стеку).
  Расшифровка `addr2line`: `QTableView::paintEvent → ...
  → RecordTableModel::rowCount (RecordTableModel.cpp:260)
  → RecordTableData::size() → SEGV на висячем указателе`.
  Корень: `KnowTreeModel::reload()` (commit синка прямо в
  GUI-потоке) удаляет все `TreeItem`, а `RecordTableModel::table`
  продолжает указывать на мертвый `RecordTableData` (`nullptr`
  проверяется, висячий — нет). Первая же перерисовка/клик —
  падение. Тот же класс опасности был в деструкторе
  (`MainWindow::~MainWindow`, коммент про `detachModels`).
  Фикс (`ab7fe08d`): `TreeScreen` на `modelAboutToBeReset`
  запоминает ветку и отцепляет таблицы записей/аттачей
  (`setTableData(nullptr)`), на `modelReset` восстанавливает выбор
  по id (кроме заблокированных шифрованных — чтобы не дёргать
  диалог пароля). Проверка пользователем: пересобрать GUI-билд,
  `MYTETRA_SYNC_DEBUG=1 ./mytetra`, синк, клик по заметке —
  в консоли должны быть строки `TreeScreen: model reset, ...`,
  падения быть не должно.
  Стенд (`/tmp/opencode/syncrepro`, два инстанса локально,
  `--sync-to`): простая заметка и заметка
  с аттачем синкаются чисто, XML на хабе валиден, файлы на месте.
  Поставленные защиты (коммиты `793d5702`, `ba03c108`):
  - `KnowTreeModel::getRecord` — null-safe (был голый
    `getItem(path)->...->getRecordById(...)` без единой проверки);
  - `EditorShowTextDispatcher`, `RecordTableController` — варнинг
    вместо падения при протухшей позиции/id после reload;
  - `serializeNote` — неизвестный тип аттача даёт пропускаемую
    ошибку записи, а не `criticalError` на всю сессию.
  Найдено попутно (не краш, но потеря данных):
  - **display-имя аттача теряется при синке**: шлётся только
    внутреннее имя (`att01.txt` вместо `doc.txt`), приём пишет его
    как отображаемое.
- **Сегфолт после синхронизации** — см. выше: корень найден
  (висячий `RecordTableData` после `reload`), фикс `ab7fe08d`,
  на проверке у пользователя. Ловушка и трассировка остаются:
  как снять лог для разбора любого следующего падения:
  1. Обе стороны запускать с `MYTETRA_SYNC_DEBUG=1`, например:
     `MYTETRA_SYNC_DEBUG=1 QT_QPA_PLATFORM=offscreen ./mytetra --sync-server --sync-port 47779 --sync-pair testpin`
  2. После падения прислать: **весь вывод консоли целиком**
     (там будет `Sync CRASH signal=...` + стек `backtrace`),
     плюс файл `<workdir>/syncdebug.log` (и `.old` при наличии).
     Стек виден даже без флага дебага — ловушка всегда включена.
- **CPU ~80% на ПК во время превью синка** (падает по Cancel).
  Разделить виноватых: диспетчер задач во время превью — эмулятор
  или mytetra-хаб. Оптимизация отрисовки (кеширование кистей/фигур,
  меньше аллокаций в `onDraw`) — в планах.
- Линии дерева в главном списке веток («пустые квадраты») — см.
  `docs/sync-plans.md`, раздел A.
