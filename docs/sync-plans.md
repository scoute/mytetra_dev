## A. Линии дерева в главном списке веток

Статус: TODO — баг от 2026-11-16 16:26 (скриншот).
Имена веток сдвинулись вправо (отступ 24dp/уровень применился),
но ЛИНИИ НЕ ВИДНО: вместо них пустые квадраты.
Подозрения для разбора:
1. NodeTreeView рисует под непрозрачным фоном строки/заголовка
   (порядок вложенности в list_item_node.xml);
2. строки не видны на светлой теме (цвет/толщина линии);
3. NodeTreeView получает нулевую высоту при onDraw (не меряется).
Проверять на светлой теме списка веток.

Причина: обсуждали «ascii-дерево», но в `NodesListAdapter`/`list_item_node.xml`
кода линий не появилось (лист перешёл к окну синка). Линии есть только в
`SyncChangesMapView.drawTreeLines` (окно синка).

Решение: канвас-рисование (не ascii-префикс: значки веток то есть, то нет,
текст поехал бы относительно колонок).

- Новый `ui/node/NodeTreeView` — кастомная View на весь размер строки, рисует
  под контентом: направляющие колонки предков (вертикаль, пока предок не
  последний среди соседей), уголок-локоть к узлу, линия вниз к детям.
- `list_item_node.xml` — `NodeTreeView` первым элементом (за контентом).
- `NodesListAdapter` — при бинде: уровень (`node.level`), цепочка
  «последний среди соседей» для узла и предков (`parentNode.subNodes`,
  для корней — список из `setDataItems`), раскрытие (линия к детям).
  Отступ уровней в dp: 24dp/уровень (было 20 сырых px).

## B. Материал для трёх вкладок окна синка (правки на сервере)

Статус: ожидает.

После перепары журнал очистился (tombstone'ы сброшены, «Ветка №2» воскресла —
ожидаемо). Материал для вкладок (хаб остановить → править → поднять):

| Вкладка | Правка на сервере | Результат |
|---|---|---|
| ↑ Я → сервер | Убрать «Ещё ветка с сервера» + 2 заметки БЕЗ надгробий | Телефон перезальёт копии: +1 ветка +2 заметки вверх |
| ↓ Сервер → я | Добавить «Ветка для вкладки Сервер→я» + 2 заметки; удалить «Ветка для проверки №2» С надгробиями | +1 +2 вниз, −1 −1 вниз |
| ⇅ Обоюдные | Правка текста: «Заметка с сервера», «Заметка уровень 2», «Заметка уровень 4» (хеш+mtime в сайдкаре) | ~3 с поединком версий |

Оговорка: ветки в «Обоюдных» невозможны (нет текста) — живут в 1-й/2-й.

Механика ↑: удаление без надгробия = безопасное «пропало ≠ удалено»,
телефон воскресит свои копии и зашлёт наверх (данные не теряются).

## D. Meld-стиль UI синка — РЕАЛИЗОВАН (десктоп, стрелки)

Сумасшедшая идея от 2026-11-18: окно синка как meld — слева моё дерево,
справа серверное, копирование стрелками/перетаскиванием в нужную сторону,
конфликт = копирование с заменой + предпросмотр. Синк и есть два
копирования (туда/обратно), UI рассматривает их отдельно.

Решения (были согласованы, реализованы):
- Только десктоп (нужна ширина), мобилу не трогаем.
- Одна таблица, строка = один id: слева моё имя, справа ихнее, в центре
  стрелки →/←. Иерархия — схлопываемыми группами (шапка = сама ветка
  со счётчиком разбора, контекст-предки — приглушённые заголовки);
  виртуализация штатная (QTreeView + иерархическая модель).
- Удаления — надгробия (серая строка на своей стороне, стрелка в сторону
  живой копии = воскрешение); переименование — одна строка с обоими именами.
- Stage + «Применить» (не немедленное применение).
- Режим «Дерево | Meld» (переключатель ⇄ Meld в тулбаре): одно окно,
  те же решения. Откат — в один клик, старое дерево цело.
- Семантика стрелок: → = «сделать как у меня», ← = «как у них»
  (Create — только своя стрелка; Edit/Rename-дуэли — ForceMine/TakeServer;
  удаления — в сторону надгробия подтвердить, в сторону живой воскресить;
  повторный тап снимает решение).
- Вкладки в meld-режиме фильтруют (направление целиком), в дереве —
  по-прежнему якоря без фильтра.
- Таблица показывает РЕЗУЛЬТАТ после «Применить» (сторона-получатель —
  твёрдая зелёная, умирающая — «—», источник копии остаётся как был).
  Пустая сторона до решения — серый пунктир
  (подсказка «сюда может приехать»), тултипы стрелок — с исходом.
- Bulk в один клик: кнопки «⭢ все / ⭠ все» (фильтр уважаем,
  повторный тап снимает), контекстное меню «всё поддерево»,
  меню «Действия по умолчанию» — по категориям целиком.
  Дерево пока остаётся фолбэком; выпил — отдельным решением
  после обкатки bulk на реальных планах.
- Замер offscreen: `docs/sync-meld-mockup.html` остаётся историческим
  макетом.

Отложено вторым слоем: drag-and-drop пилюль мышью, галка «применять
сразу» (несовместима с текущим UI — отдельная идея).
