# План развития UI синхронизации (MyTetra + MyTetroid)

Статус: рабочий документ. Составлен по итогам разбора реальных путей
пользователя в коде (`MainWindow`, `SyncDevicesDialog`,
`SyncPreviewDialog`, `MainActivity`, `SyncPrompts`, `SyncDevicesActivity`,
настройки `prefs_sync.xml` / `storage_prefs_sync.xml`).

Цель: одна понятная дверь к каждой задаче синка, минимум лишних кликов,
одинаковые правила на десктопе и мобиле, никаких молчаливых решений.

---

## 1. Как задачи проходятся сейчас

| Задача | Десктоп | Мобила |
|---|---|---|
| Обычный синк, 1 пара | иконка в тулбаре таблицы записей → (превью) → отчёт | ⋮ → «Синхронизировать» → прогресс → отчёт |
| Обычный синк, N пар | иконка → меню выбора пары | выбора нет: синкается активный хаб (какой — не видно) |
| Выбрать/сменить хаб | Sync → Sync devices → строка → Sync | ⋮ → Настройки → Sync → Устройства → тап по хабу |
| Добавить устройство | Sync → Sync devices → IP/порт → Sync now → PIN | там же → «Добавить вручную» → IP/порт → OK → синк → PIN |
| Спариться | инициатор: Sync now → PIN; второй: попап → Accept → тот же PIN | PIN вводится при первом синке; попапа/фингерпринта нет |
| Настройки синка | Tools → Preferences → Syncro | ⋮ → Настройки → Sync (и отдельно настройки хранилища → Sync) |
| Синк ветки | правый клик по ветке | долгое нажатие по ветке |
| Статус «всё ли синхронизировано» | нет, только запуск синка | нет, только запуск синка |

---

## 2. Что уже хорошо (не ломать)

- Один клик для обычного синка при одной паре; при N парах — меню.
- Превью с категориями, git-diff, единым правилом ✓/✕ и безопасными
  дефолтами (создание — молча, остальное — решать).
- Входящий запрос на пару на десктопе показывается сам.
- Мобильный экран устройств: автоскан, тап = синк, редкое — по долгому.
- Мобильный прогресс подробный; окно не закрывается посреди применения.
- Частичное «Применить» с честным вопросом «только N из M?».
- Scope-синк ветки на обеих платформах; свайп «только это» на мобиле.

## 3. Проблемы

### 3.1 Навигация

1. В меню `Sync` нет самого «синхронизировать» — только сервер,
   устройства и pairing info. Главная задача живёт в иконке тулбара.
2. В mobile-режиме интерфейса десктопа иконка синка не добавляется
   (`RecordTableScreen.cpp`: `insertActionAsButton` только для desktop).
3. Мобила: управление хабами — только из настроек; главное действие
   синкает «активный» хаб, не показывая какой.
4. Мобила: два разных «Sync» в настройках (общие — native + легаси,
   хранилище — только легаси). Легаси-поля дублируются.
5. Мобила: спаривание спрятано за первым синком; нет отдельного
   «Сопрячь», списка «кто стучится», фингерпринта хаба.
6. `Sync pairing info…` — не информация, а скрытая третья дверь к паре
   (иногда показывает текст, иногда запускает спаривание).

### 3.2 Спаривание

1. PIN никто не генерирует: его придумывает и вводит пользователь на
   двух устройствах в правильном порядке. Нет «показать PIN»/QR.
2. Фингерпринт — 64 hex-символа, на мобиле при вводе PIN не показан;
   это хэш публичного id (сверка ничего не доказывает).
3. Десктоп: два конкурирующих способа — `Pair…` и `Sync now` с ручным
   адресом; кнопки `Sync`/`Sync now` называются почти одинаково.
4. Мобильный список показывает «спарено с <deviceId>», а не с именем
   хаба; маркер «активный» — про адрес, не про пару.

### 3.3 Превью и решения

1. **Разная семантика «Применить».** Из тулбара — частичный синк
   (вопрос «только N из M?»), из окна устройств `partialSyncer` не
   передаётся: неразобранные (`Confirm`) остаются в плане и
   **применяются молча**. Опасно.
2. Десктоп: нет «✓ всё видимое» в дереве (только дефолты категорий и
   контекст ветки); в «Сравнении» — есть.
3. Мобила: нет «✓/✕ поддерево» (десктопный контекст ветки не перенесён).
4. Терминология разная: 5 категорий + «Наша/Ихняя/Diff» + «Дерево |
   Сравнение» против 3 вкладок «Туда/Откуда/Обоюдные» + «Запомнить».
5. «Запомнить» осталось на мобиле и убрано на десктопе — платформы
   учат разному.
6. Три способа решить строку: ✓/✕, панель «Наша/Ихняя», стрелки в
   «Сравнении».
7. Мобильный diff — отдельное окно с сетевым запросом на каждый тап,
   без кэша; десктопный — встроен.
8. Десктопный pre-flight тянет «ихнюю» версию для каждой Edit-записи
   до показа окна; на 2+ устройствах из-за legacy-секрета она пустая,
   и каждая правка автоматически получает `ForceMine`.

### 3.4 Прогресс, отчёт, статус

1. Десктоп: нет окна прогресса передачи — окно замирает на 100k.
2. Мобила: два прогресса одновременно (общий + кастомный).
3. Мобила: модальный отчёт после каждого синка, включая автосинк при
   старте; при недоступном хабе — модальная ошибка на каждом запуске.
4. Отчёты без «Копировать»; мобильный склеивает все `itemErrors`;
   шаги сессии на мобиле не показываются.
5. Нет статуса «последний синк» (время/результат/активный хаб).
6. Десктоп: галочка сервера без порта/статуса; при занятом порте при
   старте снимается **молча**.
7. Фоновый синк невидим (нет индикатора/бейджа).

### 3.5 Логика и настройки

1. Native-синк при старте десктопа не работает при пустой legacy-команде
   (`main.cpp` требует и галку, и команду). В native-режиме поле команды
   отключено → галка «Synchronize at startup» обманывает.
2. Страница Syncro смешивает native и legacy: команда, период, старт/выход,
   периодическая проверка базы, фон 15 минут.
3. Мобила: тап «Синхронизировать» без хоста и без legacy-профиля ничего
   не делает и молчит.
4. Scope + деструктивная стратегия («взять с хаба» / «заменить сервер»)
   молча сбрасывает scope и стирает **всю** базу.

## 4. Целевые сценарии

### Десктоп

- **Тулбар:** иконка синка. 1 пара — сразу синк; N — меню пар.
- **Меню Sync:** `Синхронизировать…` (та же логика), `Устройства и
  статус…`, `Сервер синхронизации` (галочка + порт/статус в подсказке),
  `Настройки синхронизации…`.
- **Окно «Синхронизация»:** вкладки *Устройства* (список, пара/взаимность,
  последний синк), *Сейчас* (выбрать пару, запустить, прогресс, отчёт),
  *Настройки* (native primary, legacy — «Дополнительно»).
- **Применить:** всегда «Применить решённое (N)»; полное применение —
  только когда всё разобрано.
- **Прогресс:** фаза + счётчики + скорость; отмена — «после текущего
  элемента» с предупреждением (не мгновенная).

### Мобила

- **⋮ → «Синхронизировать»:** если хабов >1 — выбор хаба (активный
  сверху); заголовок пункта — «Синхронизировать с <хаб>».
- **⋮ → «Устройства синхронизации»:** сразу экран со сканом/списком/парой.
- **Настройки → Sync:** только конфигурация (native primary, легаси —
  «Дополнительно»), без запуска синка.
- **Автосинк при старте:** тихий; отчёт — только при ошибках/удалениях,
  иначе короткий toast.
- **Спаривание:** «Показать PIN» на инициаторе, ввод на второй стороне,
  фингерпринт/имя хаба до ввода; после — «Готово».

## 5. План

### P0 — опасно / ломает доверие

- [x] Одинаковая семантика «Применить» в обоих входах (частичная).
- [x] Native-синк при старте десктопа (не требовать legacy-команду).
- [x] Занятый порт сервера — не молчать, показать причину.
- [x] Scope + деструктивная стратегия — запрет (ошибка с объяснением),
      никакого `wipeAll`/`reset` для синка ветки.
- [x] Мобильный автосинк при старте — без модального отчёта при успехе.

### P1 — лишние клики и раздражение

- [x] `Синхронизировать…` в меню Sync; кнопка синка в mobile-режиме.
- [x] Мобила: выбор хаба при синке; пункт «Устройства синхронизации»
      в главном ⋮.
- [x] Один прогресс на мобиле (кастомный показывать сразу).
- [x] Отчёты: «Копировать», первые N ошибок + «ещё…».
- [x] Кнопки устройств: «Синхронизировать выбранное» /
      «Подключиться по адресу…» (ручной адрес — отдельным шагом позже).
- [x] Статус последнего синка в окне устройств (время/результат).
- [x] Подсказка, если «Синхронизировать» нажали без хоста.

### P2 — паритет и полировка

- [ ] Единые вкладки/категории превью на обеих платформах.
- [x] «✓/✕ поддерево» на мобиле.
- [x] Кэш diff на мобиле (inline — остаётся).
- [ ] «Запомнить» на десктопе (или убрать на мобиле).
- [ ] Мастер PIN/QR, короткий фингерпринт.
- [ ] Онбординг первого запуска (карточка «Синхронизировать с ПК»).
- [ ] Индикатор фонового синка (трей/бейдж).
- [ ] Desctop: прогресс передачи с безопасной отменой.
